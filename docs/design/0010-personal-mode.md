# 0010 Personal 模式

状态：当前设计 · 更新：2026-11-07

## 范围与现状

Personal 围绕长期伙伴交代事情，交付答案、办完的事和产物。

当前 Personal 使用普通 `Session{mode: personal}`：名字是会话标题，头像取首字。独立伙伴实体、人格入口、产物与转交服务尚未实现。

| 状态 | 边界 |
|---|---|
| ◐ 代码现状 | Personal 是普通 Session，标题和首字头像表示伙伴 |
| ○ 目标 | 伙伴实体与人格、委派子会话与回报、产物和转交 Code |

## 伙伴与事情

```mermaid
flowchart TB
    Me["我"] <--> Main["伙伴主会话<br/>交流 · 协调 · 汇报"]
    Main --> A["事情 A"]
    Main --> B["事情 B"]
    A --> HA["委派子会话"]
    B --> HB["委派子会话"]
    HA --> Results["结果与产物"]
    HB --> Results
    Results --> Main
```

| 概念 | 当前规则 |
|---|---|
| 伙伴 | 人格 + 所选 harness + 连续主会话；各伙伴可选不同 harness |
| 事情 | 围绕目标、要求和结果跟进；不设单独实体，一件事由一个委派子会话承担 |
| 会话 | 保持当前统一 Session 内核；不将原生子执行自动视为新 Session |
| 参与者 | 消息记录发言伙伴，v1 只有一个参与者 |
| 生命周期 | 伙伴长期存在；轮次结束不证明事情完成 |

## 委派与回报

目标，尚未实现。

```mermaid
flowchart LR
    Main["伙伴主会话"] -- "session_create / session_send" --> Child["委派子会话<br/>Personal · 托管"]
    Child -- "report" --> Box[("持久回报")]
    Box -- "空闲投递 / 忙时排队" --> Main
    Main -- "handoff" --> Code["Code 会话<br/>属于我"]
    Code -- "轮次结束 / 等待审批" --> Box
```

| 项 | 规则 |
|---|---|
| 委派 | 伙伴用 `session_create` 建 Personal 子会话，归属为托管，关联父会话；用 `session_send` 继续交代 |
| 回报 | 子会话用 `report` 交回结果；结果持久记录，父会话空闲时投递，忙时排队，不因投递失败丢失 |
| 原生委派 | harness 自己的子代理照常可用，Hoplet 不把它当作事情跟踪 |
| 转交 Code | `handoff` 建归属于我的 Code 会话，带目录、摘要和回到伙伴的关联；它的轮次结束或等待审批时回报伙伴 |

## 选择与位置

| 项 | 规则 |
|---|---|
| 模式 | 我明确选择 Personal，不由模型猜测 |
| harness | Personal 默认 harness 是设置项；新建伙伴时默认使用，可选择其他已支持项 |
| 模型登录 | 订阅或 API key 由 harness 自己管理，Hoplet 不保管凭证 |
| 人格 | 各伙伴独立；不擅自改写用户全局人格配置；见下节 |
| 位置 | 可建在任一自有主机，默认常驻主宿主；列表按机器筛选 |
| 跨机 | 需要另一台机器的操作交给明确授权的远端执行 |

## 人格

目标，尚未实现。

| 项 | 规则 |
|---|---|
| 来源 | 每个伙伴一份 `~/.hoplet/companions/<id>/persona.md`，是唯一来源 |
| 工作目录 | 伙伴主会话的工作目录是 `~/.hoplet/companions/<id>/`；项目里的工作交给子会话在各自目录进行 |
| Claude Code | 启动时读 `persona.md`，经 `--append-system-prompt` 传入 |
| Hermes | 每次启动伙伴时用 `persona.md` 覆盖生成同目录的 `HERMES.md`，开头注明由 Hoplet 生成、直接修改会被覆盖；Hermes 从工作目录读取 |
| 叠加 | 人格叠加在 harness 自身的全局身份之上，不替换也不修改它 |
| 生效 | 改动保证对新主会话生效；Claude Code 伙伴下次启动即生效；Hermes 把系统提示冻结在会话上，已有主会话不保证生效 |
| 限制 | Hermes 对 `HERMES.md` 做注入扫描，命中的内容被丢弃且不报错；Hoplet 不另做检测 |

## 能力边界

```mermaid
flowchart LR
    P["Personal"] -- "转交变更工作" --> C["Code"]
    C -- "结果 / 进度" --> P
    P -- "按范围查询与提交" --> M[("共享成长记忆")]
    P --> Artifacts["会话产物"]
```

| 能力 | 规则 |
|---|---|
| 交流 | 短回答、澄清、优先级调整与结果汇报由主会话承接 |
| 执行 | 复用 harness 的工具、技能与原生委派；异步能力按版本验证 |
| 成长 | 使用内核的可迁移记忆；不以原生 Memory 自动代替权威档案 |
| Code 互通 | 提供目录、摘要与关联；给我已有会话发消息须先托管 |
| 产物 | 与事情和会话关联，可回到来源查看 |
| 权限 | 延续原生审批与 Hoplet 工具规则；记忆不授予授权 |
| 范围外 | 群聊与 Personal 代批不在 v1 范围内 |

## 验收

| 场景 | 结果 |
|---|---|
| 离开后回来 | 继续同一伙伴的交流，知道未完成事项 |
| 交代多件事 | 能区分目标、修订和结果，执行状态可追踪 |
| 转交 Code | 带目录与摘要，结果回到伙伴并等待我审阅变更 |

主会话与事情的图示是组织目标，不冻结新实体、接口或界面。未验证的能力不作为当前已实现功能呈现。
